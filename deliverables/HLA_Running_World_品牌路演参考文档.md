# HLA Running World｜江苏数字跑步赛季

## 品牌共创参考方案

面向：海澜之家 / HLA POW 澜跑 / 澜跑研习社 / 赛事与社群合作团队

**一句话定位：**把真实跑步，变成品牌与跑者之间持续发生的数字陪伴。

## 1. 交流出发点

这份方案不是在向品牌方推销一个已经成熟的产品，也不是要求品牌方立刻提供活动资源。它更像一次真诚的想法交流：我从跑者训练中的孤独、重复、反馈不足出发，做了一个可点击 Demo，希望和海澜之家一起讨论它是否有机会成为品牌体育生态中的数字体验层。

跑者在马拉松训练中，每周都在付出真实努力，但这些努力往往只被记录成距离、配速和卡路里。对普通跑者来说，这些数字很难持续带来故事感、目标感和社群动力。

海澜之家已经拥有赛事、跑团、装备、体育公园和城市场景。Running World 希望补充的是：让用户在赛事前后和日常训练里，也能持续感到品牌陪伴。

## 2. 品牌机会

**现有资产：**无锡马拉松、江阴半马/越野赛事、澜跑研习社、HLA POW 澜跑、飞马体育公园、江阴/无锡城市场景。

**数字补充：**数字训练赛季、真实地图路线、路线节点、跑团榜单、AI 陪跑反馈、分享卡、徽章与品牌权益。

**商业价值：**

- 把一次赛事曝光延展为长期训练陪伴。
- 提升跑团活跃、会员触达和装备权益转化。
- 把跑者训练行为转化为可传播的品牌内容。
- 让线下赛事、城市节点和品牌故事在日常跑步中持续出现。

## 3. 产品闭环

- 用户选择江苏 / 江阴 / 锡马主题路线，进入品牌数字赛季。
- 每日跑步后输入距离，系统累计推进数字分身。
- 抵达关键节点后解锁城市故事、品牌彩蛋、徽章或奖励提示。
- AI 陪跑者根据最近跑量、连续训练天数和当前进度生成反馈。
- 用户在个人页看到自己的赛季状态、个人排名、跑团排名、徽章权益和跑团榜。
- 用户生成分享卡，转发到朋友圈、微信群、小红书或跑团社群。

## 4. 当前 Demo 状态

本轮 Demo 采用移动优先 H5，已实现品牌赛季首页、真实地图路线推进页、跑后反馈页、分享卡生成页和个人赛季页。V0.6 已补上内部转发所需的最小多人体验：每个浏览器生成本地匿名访客身份，跑量、路线和分享卡状态互相独立地保存在本机浏览器中。

演示版本在本地开发时可使用高德真实地图、国内 AI 陪跑代理和社区/跑团模拟数据；临时线上预览版默认使用本地地图与规则型 AI 反馈，减少手机访问时的等待和外部服务依赖，适合通过腾讯 CloudBase 默认域名给品牌内部先做点击体验。

需要特别说明：当前 Demo 只是概念示意，用来帮助讨论体验逻辑、用户路径和品牌价值，不代表最终产品形态。真正产品化前，需要品牌、赛事运营、社群运营和技术团队共同定义。

## 5. 建议路演讲法

1. 先说明自己不是来卖成熟产品，而是带着跑者视角、年轻技术视角和 Demo 来交流。
2. 讲跑者训练痛点：孤独、重复、缺乏即时反馈和持续动力。
3. 讲品牌机会：线下赛事和跑团资源已经很强，但日常训练中的线上陪伴关系可以继续加强。
4. 展示核心逻辑：真实跑步 -> 路线推进 -> 节点故事 -> AI 反馈 -> 个人页/跑团榜 -> 分享传播。
5. 展示 Demo：重点让对方理解体验闭环，而不是把 Demo 当成最终产品验收。
6. 提出共创想象：后续由品牌、赛事运营和技术团队共同定义完整产品，我可以作为外部技术顾问或项目参与者协助。

## 8. 常见问题

**这是不是已经能上线的产品？**  
不是。当前是概念 Demo，用来帮助讨论体验逻辑；正式上线前需要品牌、赛事运营和技术团队共同设计。

**用户乱填距离怎么办？**  
概念阶段先展示闭环。正式活动可加入凭证上传、异常识别和第三方运动平台同步。

**是否采集敏感运动数据？**  
当前临时预览只在浏览器本地保存匿名访客身份、路线选择和手动跑量，不上传到正式数据库。正式产品如需运动平台同步，必须基于用户授权。

**没有用户怎么办？**  
优先从澜跑研习社、合作跑团、员工健康活动、赛事报名用户和本地跑者社群中寻找自然入口。

**后续谁来开发？**  
理想模式是由品牌方技术部门或合作供应商主导完整产品开发，我可以作为外部技术顾问或项目参与者参与产品定义、Demo 验证和体验优化。

## 9. 希望品牌方共同确认

- 哪类用户最适合作为首个目标人群。
- 哪条路线最适合海澜之家当前品牌场景。
- 哪些城市节点、赛事资源、品牌故事和权益可以被写入体验。
- 数据采集、排行榜展示和运动平台同步的边界。
- 后续由品牌、赛事、社群、技术或会员团队中的谁继续评估。

建议下一步不是直接立项，而是安排一次 30-45 分钟共创评估会，把这个想法放进海澜之家的真实业务语境里讨论。
